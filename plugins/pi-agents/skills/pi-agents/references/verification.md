# Reports, evidence, and parent review

Read the compact state and summary first. A worker report identifies outcome, actual coverage and gaps, findings and caveats, changes, checks run or omitted, blockers, and next action. Negative findings name inspected bounds. A missing or invalid report cannot establish completion.

For code, inspect the entire captured change manifest and relevant diff, including staged changes, new files, deletions, and binary metadata. Compare it with declared writes and the baseline. Rerun or inspect check evidence as needed; reported checks are worker assertions. For research or audits, verify original sources and contrary evidence for adopted claims. Refresh evidence if the live workspace changed after capture.

Record a parent-owned review against the execution and evidence hashes. Mark every required criterion with inspected evidence and explain freshness, gaps, and integration checks. Use `awaiting_evidence` or `needs_correction` when required output is missing. A worker exit, valid report schema, or worker claim is not acceptance. Preserve earlier reports through corrections.

For an `accepted` review, cite each inspected execution artifact as `artifact:<artifact_id>@sha256:<hash>`, using the ID and SHA-256 shown by `pi_get_task`. Each cited artifact must belong to the reviewed execution. Do not substitute a file path or a worker's unsupported evidence claim for a captured artifact reference.

Every element of accepted-review `criteria[].evidence` must contain only a citation. Put explanatory text in review-level `rationale`, `freshness`, or `integration_checks`. For example, use `evidence: ["artifact:artifact_report@sha256:<actual-64-hex-hash>"]` with `rationale: "Parent verified the original sources"`; adding that sentence as a second evidence element is invalid. Correctable citation errors return `INVALID_INPUT`, `change_input`, the criterion ID, evidence index, and malformed-reference/unknown-artifact/hash-mismatch reason. Observe the current revision and use a new idempotency key for a corrected payload.

Artifact reads in 0.2.0 return one body representation in `structuredContent`; read that object without printing the complete MCP envelope. `encoding: "auto"` (the default) returns `content` for valid complete UTF-8 text/JSON ranges and `content_base64` for binary, invalid UTF-8, or a range splitting a character. The returned `encoding` identifies the representation. Byte offsets and hashes always describe original bytes. Request `encoding: "base64"` for exact-byte reconstruction, or use CLI `artifacts export` to export and verify the full artifact. Explicit `encoding: "text"` rejects incomplete/invalid UTF-8 with correction guidance. Concatenate decoded bytes using `next_offset` for pagination; never assume all auto chunks are text. The 0.2.0 contract removes duplicate body fields; older consumers requiring base64 should request it explicitly.

For audits with must-inspect bounds, compare every required file and check with the actual per-file inspected, sampled, or not-inspected status. Missing required coverage calls for `awaiting_evidence` or `needs_correction`; report validity and truthful limits do not satisfy an unmet coverage criterion.
