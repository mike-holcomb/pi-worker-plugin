# Pi Agents v0.2.0

Release candidate addressing issues 1–6 in the parent review and documentation-audit workflow. Plugin, runtime, diagnostics, and MCP identify as `0.2.0`. Version 0.1.0 remains the published stable release until this candidate is reviewed, merged, tagged, and published.

## Changes

- Return actionable accepted-review input errors with criterion and evidence-index details (#1).
- Explain profile capabilities and parent ownership of Git and shell-based checks before dispatch (#2).
- Return one artifact-body representation and compact MCP text framing, preserving byte-exact reads (#3).
- Expose whether a worker checkpoint has been observed, separately from channel support, and document quiet-worker supervision (#4).
- Add explicit per-file audit bounds and paired frozen evaluations for sampled and complete coverage (#5).
- Add the read-only `pi_prepare_review` MCP tool with exact execution identity, paginated criteria, artifact citations, and review templates (#6).

## Compatibility and upgrade

Pi Durable remains pinned to 1.5.0, Node remains `>=24.15 <25`, and no SQLite migration is introduced. The MCP surface grows from eleven to twelve tools. New final manifests record explicit artifact roles; older manifests remain readable without invented role metadata.

`pi_read_artifact` accepts `encoding: "auto" | "text" | "base64"`, defaulting to auto. Its response includes the resolved encoding and exactly one of `content` or `content_base64`. Auto returns base64 for binary or non-decodable UTF-8 byte slices. Clients that previously assumed base64 was always present must request it explicitly; CLI export already does so. Offsets, immutable hashes, and byte lengths retain their existing meaning.

Accepted-review evidence remains citation-only; prose belongs in review-level rationale, freshness, or integration checks. Malformed evidence now returns input-correction guidance rather than a generic lifecycle conflict. Review preparation never establishes criterion satisfaction or parent acceptance. Collect all preparation pages and inspect the referenced evidence before submitting a review.

Reconcile active work and stop resolved workers and the daemon before replacing the runtime. Back up state and reports, and start a fresh Codex session. See the [installation and rollback guide](../../plugins/pi-agents/docs/installation.md).

## Install and assets

Use local installation to try this candidate. After publication, install with:

```bash
codex plugin marketplace add mike-holcomb/pi-worker-plugin --ref v0.2.0
codex plugin add pi-agents@pi-worker-plugin
```

Candidate assets are `pi-agents-v0.2.0.zip`, its `.manifest.json`, and its `.sha256` sidecar. Keep all three together. Verify with `sha256sum -c pi-agents-v0.2.0.zip.sha256` on Linux or `shasum -a 256 -c pi-agents-v0.2.0.zip.sha256` on macOS.

## Validation and limits

Regression tests cover review input rejection without state changes, byte-exact artifact encoding and export, checkpoint observation and progress-aware waits, coverage fixture integrity, and read-only review preparation across pagination, continuation, and stale state. Release checks include generated schemas, source-to-executable correspondence, deterministic packaging, and relocated read-only installed smoke. CI runs Node 24.15.0 and 24.22.1 on macOS and Ubuntu; the PR records the observed results.

Scripted providers verify checkpoint publication and ingestion; they do not establish live model checkpoint reliability or audit quality. Hosted-provider execution, fresh-client marketplace installation, hostile filesystem concurrency, and machine power-loss durability require separate evidence. Approved arbitrary shell commands run as the host user. See [validation](../../plugins/pi-agents/docs/validation.md).
