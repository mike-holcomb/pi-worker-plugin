# Pi Agents v0.2.0

Stable release addressing issues 1–10 in parent review, permission coordination, and bounded worker workflows. Plugin, runtime, diagnostics, and MCP identify as `0.2.0`.

## Changes

- Return actionable accepted-review input errors with criterion and evidence-index details (#1).
- Explain profile capabilities and parent ownership of Git and shell-based checks before dispatch (#2).
- Return one artifact-body representation and compact MCP text framing, preserving byte-exact reads (#3).
- Expose whether a worker checkpoint has been observed, separately from channel support, and document quiet-worker supervision (#4).
- Add explicit per-file audit bounds and paired frozen evaluations for sampled and complete coverage (#5).
- Add the read-only `pi_prepare_review` MCP tool with exact execution identity, paginated criteria, artifact citations, and review templates (#6).
- Prevent native permission request ID collisions across executions and migrate durable stores with a pre-upgrade backup (#7).
- Add opt-in daemon/local shell readiness metadata and synthetic tsx evaluations (#8).
- Clarify per-effect approvals and evaluate edit batching without adding standing grants (#9).
- Deliver optional `worker_explanation` with exact permission denials while keeping `authorization_basis` audit-only (#10).

## Compatibility and upgrade

Pi Durable remains pinned to 1.5.0, Node remains `>=24.15 <25`, and durable stores migrate transactionally to SQLite schema 4 after a private backup. Native request IDs now use an execution-scoped key; all prior request states, bindings, and reply keys are retained. Older runtimes cannot open schema 4; rollback requires restoring the matching backup. The MCP surface grows from eleven to twelve tools. New final manifests record explicit artifact roles; older manifests remain readable without invented role metadata.

`pi_read_artifact` accepts `encoding: "auto" | "text" | "base64"`, defaulting to auto. Its response includes the resolved encoding and exactly one of `content` or `content_base64`. Auto returns base64 for binary or non-decodable UTF-8 byte slices. Clients that previously assumed base64 was always present must request it explicitly; CLI export already does so. Offsets, immutable hashes, and byte lengths retain their existing meaning.

Accepted-review evidence remains citation-only; prose belongs in review-level rationale, freshness, or integration checks. Malformed evidence now returns input-correction guidance rather than a generic lifecycle conflict. Review preparation never establishes criterion satisfaction or parent acceptance. Collect all preparation pages and inspect the referenced evidence before submitting a review.

`pi_health` accepts optional `shell_preflight: true`; `doctor --shell-preflight` reports local-process readiness. These fixed probes do not run project checks or inference. `pi_respond_to_request` accepts optional `worker_explanation` only for permission denial, limited to 4,096 UTF-8 bytes. Its worker acknowledgement does not establish model compliance. Existing payloads and exact `allow_once` semantics remain valid.

Reconcile active work and stop resolved workers and the daemon before replacing the runtime. Back up state and reports, and start a fresh Codex session. See the [installation and rollback guide](../../plugins/pi-agents/docs/installation.md).

## Install and assets

Install the published release with:

```bash
codex plugin marketplace add mike-holcomb/pi-worker-plugin --ref v0.2.0
codex plugin add pi-agents@pi-worker-plugin
```

Release assets are `pi-agents-v0.2.0.zip`, its `.manifest.json`, and its `.sha256` sidecar. Keep all three together. Verify with `sha256sum -c pi-agents-v0.2.0.zip.sha256` on Linux or `shasum -a 256 -c pi-agents-v0.2.0.zip.sha256` on macOS.

## Validation and limits

Regression tests additionally cover colliding native IDs across isolated backends, migration state preservation/rollback, denial context delivery and uncertain acknowledgements, private shell/IPC diagnostics, and offline approval/tsx scenarios. Existing tests cover review input rejection without state changes, byte-exact artifact encoding and export, checkpoint observation and progress-aware waits, coverage fixture integrity, and read-only review preparation across pagination, continuation, and stale state. Release checks include generated schemas, source-to-executable correspondence, deterministic packaging, and relocated read-only installed smoke. The release merge commit `6c071808f6b5efc9d9102e452f21ab926cef2ff9` passed CI on Node 24.15.0 and 24.22.1 on macOS and Ubuntu. Fresh-client marketplace registration and plugin installation from `v0.2.0` passed using an isolated Codex home; the installed plugin reports version `0.2.0` and its executable matches the tagged source.

Scripted providers verify checkpoint publication and ingestion; they do not establish live model checkpoint reliability or audit quality. Hosted-provider execution, hostile filesystem concurrency, and machine power-loss durability require separate evidence. Approved arbitrary shell commands run as the host user. See [validation](../../plugins/pi-agents/docs/validation.md).
